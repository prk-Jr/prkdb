# Main CI repair design

The linked CI runs all used main f5155d0. Repair their causes without changing audit policy, test budgets, mutation scope, or performance thresholds.

1. Replace the unmaintained chrono dependency with the already-resolved time 0.3.55. Remove unused humantime and unused chrono declarations. Keep epoch seconds/milliseconds numeric, RFC3339 JSON timestamps, SQL naive datetime text (YYYY-MM-DD HH:MM:SS), and existing RFC3339 SQL input readable. ORM Rust APIs move from chrono NaiveDateTime/DateTime<Utc> to time PrimitiveDateTime/OffsetDateTime; the maintainer approved this migration. Offset datetimes normalize to UTC for the former UTC mapping. Dashboard timestamps remain local HH:MM:SS.mmm, falling back to UTC if the OS cannot determine its offset.
2. The mutation baseline log shows both concurrent WebSocket test servers chose gRPC port 50530; one bind failed and that client reached the other database. Use OS-assigned ephemeral ports and a startup mutex through readiness to protect the reservation-to-bind handoff within the test binary. Use independent temporary database directories. Tests remain concurrent after startup.
3. WsConsumer must emit Connected only from the server message, after the server captures its latest offset. HTTP upgrade alone is not readiness. Test both single acknowledgement followed by update and initialization error before readiness; each must fail on the original client.
4. The aggregate-counter test must wait for users=1 and orders=2 before comparing the aggregate with three. Its prior condition (both counters nonzero) admits an incomplete sample. Keep exact assertions and the direct-appends assertion; change no production storage code.

Verification includes targeted regressions, ORM legacy format round-trips, workspace fmt/Clippy/nextest/doctests, remediation checks, the pre-push script, cargo deny/audit, and hosted CI/performance. Linux instruction counts cannot be measured on this Mac. No WAL format or production storage implementation changes are planned.
