# Rust 1.100 and scheduled CI coverage

Approved scope: one PR from public main at `9c4345a0636a7aaca08f3b9a28c9a12e3a0a445b`; no unpublished Phase 2 commits and no merge.

## Problems and intended behavior

Local builds and ordinary CI currently pin Rust 1.99.1. Upgrade the repository toolchain, workspace compiler requirement, ordinary CI/release actions and current setup documentation to exact 1.100.0. Preserve intentionally nightly jobs and historical evidence. Keep performance comparisons explicit about the compiler actually used by each checkout.

Scheduled CI runs 45021343915 and 45189475156 fail cargo-deny because Cargo.lock resolves url 2.5.8, affected by RUSTSEC-2026-0592. Update to 2.5.9 and require at least that patch in the direct client dependency. Preserve advisory policy; add a small regression for deep blob URL origins and ordinary HTTPS origins.

Chaos is explicitly excluded on schedule. Remove that exclusion while retaining its check/test dependencies and existing PR/push/manual coverage. The slow-test job does not replace the feature-enabled cluster suites.

Benchmarks are excluded on schedule/manual because the mutation sweep runs then. Extract the existing Kafka-reference benchmark job into a reusable workflow, preserving measurements, artifacts, caveats and failure behavior. Keep the existing push/PR caller, and add a separate schedule (12:00 UTC, offset from CI at 04:00 UTC) and manual trigger. Avoid duplicating the benchmark implementation. Separate concurrency groups and record event, SHA and actual toolchain in results. Scheduling separation reduces overlap; it does not guarantee exclusive hosted hardware or comparable wall-clock conditions.

## Acceptance and preservation

- Exact Rust 1.100.0 selected by default in this worktree; formatting, Clippy, workspace tests, doctests and pre-push checks pass.
- cargo deny and cargo audit pass without new ignores; hostile nested URL regression distinguishes patched dependency from old.
- Workflow checks cover push, PR, schedule and manual routing; chaos remains dependent on successful check/test, and benchmark callers invoke the same reusable implementation.
- actionlint has no new diagnostics; existing baseline debt must remain explicit.
- Linux instruction-count performance gate remains unchanged at 5%; hosted evidence must establish compiler/performance qualification, never inferred from Mac checks.
- Release actions receive the new pin; no release or deployment is executed.

## Alternatives

Enabling benchmarks in the scheduled CI run is smaller but repeats the previously observed mutation-load interference. A separate copied benchmark workflow drifts over time. A reusable job with independent scheduled/manual entry points preserves one implementation and existing PR coverage.

## Scope

Files: rust-toolchain.toml, Cargo.toml, Cargo.lock, crates/prkdb-client/Cargo.toml and dependency regression tests, .github/workflows/{ci,chaos-tests,perf-gate,release,remediation-gate,repo-audit,benchmarks}.yml, README.md, docs/guide/getting-started.md, workflow regression tests, and this design/companion plan. Additional compiler-required edits must be reported and kept minimal. No production hot-path edits planned.
